# 从“感觉变好了”到可检验的改动

## 第一步：手算

设相关集合为 `[a,b]`，排名为 `[x,a,b]`，k=3。Recall 是 1；MRR 是 1/2；AP 是 `(1/2+2/3)/2`。先手算，再运行测试核对。将 b 移到第一位，观察 MRR 和 nDCG 的不同敏感度。

## 第二步：做自己的评测集

从一门课的笔记提出 30 个真实问题，标注证据 ID。加入需要多个片段回答的问题，以及资料没有答案的问题。把调试问题和最终测试问题分开，避免反复看测试集调参。

## 第三步：接入检索程序

在查询前后使用 `performance.now()` 计时，记录完整检索顺序。固定语料、分块方式、ID 与 k，再比较两套算法。若引用来自文件级 ID，标注也使用文件级 ID；不要混用片段和文件。

## 第四步：解释变化

先看每个问题的 details，再看宏平均。找出 Recall 上升但 MRR 下降的例子。对比拒答准确率，避免只优化可回答问题。检查 bootstrap 区间，但不要把六个演示问题的区间解释成真实系统显著改进。

## 可继续实现

1. 在报告中列出逐问题退化最大的样本，输出原问题与证据。
2. 支持 graded relevance，让 nDCG 区分弱相关与强相关。
3. 增加分组 bootstrap，按同一文档的问题成组采样。
4. 记录运行环境、索引版本、模型版本与提示词摘要，跟踪复现条件。
5. 使用真实系统生成的运行记录替换合成数据，保留标注集版本。
